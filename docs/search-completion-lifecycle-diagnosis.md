# 검색 완료 후 화면 정체 — 2026-09-11

## 추가 재현: 공식몰 결과가 포함되면 리스트 전체 표시 중단

v2.10.704 배포 후 사용자가 보낸 화면에는 `검색 결과 화면 표시 중 오류가 발생했습니다`가 나타나며 첫 행이 검색 중 표시로 남았다. 공식몰과 무신사가 함께 있는 응답을 기존 DOM 검증에 넣자 `ReferenceError: contextKey is not defined`로 같은 오류 경로가 재현됐다.

`src/domestic-inline-results.js`의 `sourceAction`은 별도 함수인데, `inlineRenderDomestic`의 지역 인자인 `contextKey`를 직접 참조했다. 공식몰의 상세 상품 URL 없이 검색/홈페이지 링크를 표시할 때 예외가 발생해 전체 행의 HTML 생성이 중단됐다. 이 함수의 인자로 상품 키를 명시적으로 전달하도록 두 호출부를 수정했다.

- 수정 전: 공식몰 검색 링크, 상세 URL 없는 공식몰 카드, 공식몰 상품 없음 결과의 세 경우 모두 실제 ReferenceError로 실패.
- 수정 후: 기존 9개 및 추가 5개 DOM 테스트 총 14개 통과.
- 2개 상품 × 6개 판매처의 리스트 위치, 각 상품의 공식몰/네이버 결과 키, 무신사 재고 감시 버튼과 가격 표시를 검사한다.
- 이전 검증은 무신사 단독 응답만 사용해 이 공식몰 분기를 놓쳤다. 아래 내용은 최초 종료 처리 보강 당시의 기록이다.

## 확인 범위

- 사용자 화면: 실행 버전 2.10.703, 이미지 교차검증 8/8·100% 이후 수달 화면 유지.
- 기준 main: `8ab8952713147033e9f592624a195264b4c84438`.
- 같은 버전의 정상 응답은 오프라인 DOM 테스트에서 정상적으로 끝났다. 따라서 사용자 기기의 직접 원인을 확정하거나 구버전 설치 문제라고 판단할 근거는 없다.
- 실제 renderer 함수와 열 설정/소싱/인라인 결과 확장 코드를 함께 실행했다. 외부 판매처/IPC 응답은 통제한 테스트 응답이다. 실제 Windows 실행 및 실시간 판매처 검색은 검증하지 못했다.

## 재현한 결함과 수정

1. 선택 상품 검색에 최종 정리가 없어, 100% 진행 이벤트 후 결과 렌더러가 예외를 던지면 화면 잠금이 남았다. `try/catch/finally`로 정리하며 이미 받은 데이터는 유지한다.
2. renderer 제한 시간이 지나도 cancellation IPC를 다시 무기한 기다렸다. 중지는 비동기 정리 요청으로 분리하고 화면을 즉시 해제한다.
3. 단일 행의 중지 버튼은 선택 상품 검색 버튼을 눌러 새 검색을 시작할 수 있었다. 동일한 중지 함수로 연결한다.
4. 이전 검색의 늦은 응답이 재검색 화면을 덮어쓸 수 있었다. 실행 ID와 진행 이벤트 요청 ID를 검사한다.
5. 결과 갱신마다 원본 Excel을 다시 읽는 경로를 없애고 메모리 결과만 현재 행에 반영한다.
6. 판매처 단계 완료와 전체 화면 작업 완료를 구분한다. 마지막 단계는 응답 대기로 표시하고 결과 반영 후 모달을 닫는다.
